## 1. 这是什么项目

见字是 2026 知乎黑客松校园季「知识炼金场」的桌面网页。一张桌子上铺着从知乎挑出来的回答，一次只看清中间几张。读者拖桌子、用键盘跳到下一张，点中的那张会翻过来，读完开头再去知乎。

它不是学习工具，不把回答炼成要点。读者要遇见的是写字的人。

引导卡不是浮在桌上的教程，是第一次打开时**占住灯下那一格的一张剪报**。和周围的回答同一套纸、同一套拖动、同一套翻转。刷新之前它一直在；下次打开这一格换回池子里的回答。

---

## 2. 为什么要这些图

现在的引导卡是一段说明文字。桌上另外几十张卡也是大段正文。读者天生跳过说明书。操作（移动、翻开、收藏、换视图）被埋在字里。

图要做的事：让人在三秒内看见「手往哪放、键是哪几个」，而不是再读一遍底栏那行字。

这些图只给引导卡用，不进内容池，不印到知乎回答上。池子里的正文仍是接口给的原文开头，一个字不改。

## 3. 你要交付什么

文件放到 `jianzi/public/guide/`。前端按 `src` 原样引用。缺文件不要占位、不要 404 图。

| 文件 | 上哪一面 | 画面里必须有什么 | 画面里不要有什么 |
| --- | --- | --- | --- |
| `move.webp` | 正面 | **WASD** 与 **方向键** 两套键，表示同一件事：把桌子移到下一张。两套键要画成实体键帽或报纸示意图，一眼能认出。可以画一张卡在键的「前面」被送到眼前。 | 不要写成「请按 WASD」。不要游戏手柄。不要 WASD 和方向键各说各的、好像两套功能。 |
| `pointer.webp` | 正面 | 两件事并置或上下排：**(1) 笔记本触控板，两指平移**；**(2) 鼠标**，滚轮上下、Shift+滚轮左右、按下中键拖动。这是 Windows 用户会伸手去做的动作。 | 不要画成 macOS 宣传图。触控板和鼠标都要能单独看懂。不要浏览器缩放图标。 |
| `open.webp` | 背面 | 点中间那张卡，或按 **Enter / 换行**，纸翻过来。翻过去是原文开头，撕口下面才去知乎。 | 不要画成 App 弹窗。不要「点击这里」箭头贴在真实 UI 截图上。不要假知乎界面。 |
| `file.webp` | 背面 | 按住一张卡拖到屏幕**左边**三枚标签（稍后读 / 值得再读 / 想转给谁）。旁边用小键帽标 **1 / 2 / 3** 对应这三枚。 | 不要心形、五星、点赞。收藏不是喜欢。 |
| `views.webp` | 背面 | 屏幕**右边**三枚竖排索引标签：紧凑、宽松、列表。小键帽 **8 / 9 / 0** 依次对应。 | 不要汉堡菜单、不要底部 Tab Bar。 |

正面两张是进门就要看见的。背面三张跟翻开的说明走，读者点开引导卡才看到。

### 技术规格

- 格式：WebP 或 PNG。优先 WebP。不要 JPG。
- 宽度：720px（卡片内容区大约 340–380 CSS 像素，2x 足够）。高度随构图，不要做成满屏海报。
- 单张体积：小于 120KB。
- 比例：正面横图约 **2:1**（短色版，塞进灯下那张卡，高不超过约 170 CSS 像素）。背面可以 3:2。竖图不要。
- 插入方式：图不是堆在文末。写进 `GUIDE_BLOCKS` 数组，插在对应那句后面。前端按数组顺序渲染。正面两句各跟一张图；背面三张跟在翻开说明后面。

示例（文件齐了之后由前端填，你先按这个顺序交文件）：

```ts
export const GUIDE_BLOCKS = [
  { type: 'text', face: 'front', text: '桌子可以拖。方向键和 WASD 会把下一张送到眼前。' },
  { type: 'figure', face: 'front', src: '/guide/move.webp', alt: 'WASD 与方向键，移动桌子' },
  { type: 'text', face: 'front', text: '触控板两指，滚轮、Shift 滚轮、中键也能挪。' },
  { type: 'figure', face: 'front', src: '/guide/pointer.webp', alt: '触控板两指，滚轮与中键' },
  { type: 'text', face: 'back', text: '点开或按 Enter，纸会翻过来。背面是我们拿到的原文开头，撕开的地方去知乎。' },
  { type: 'figure', face: 'back', src: '/guide/open.webp', alt: '点卡或按 Enter，纸会翻开' },
  { type: 'figure', face: 'back', src: '/guide/file.webp', alt: '按住拖到左边，或按 1 2 3' },
  { type: 'figure', face: 'back', src: '/guide/views.webp', alt: '右边三个标签，或按 8 9 0' },
]
```
- 透明：不要透明底。插图是印在报纸上的一块色版，四边可以略毛，但不要悬在透明棋盘上。
- 文字：可以画键帽上的字母（W A S D、↑↓←→、1 2 3、8 9 0、Enter）。不要写句子、不要英文说明段落、不要水印、不要 Logo。中文标签如果出现，只允许「稍后读 / 值得再读 / 想转给谁 / 紧凑 / 宽松 / 列表」这些产品里已有的词。
- 交付时在本文件末尾补一张表：文件名、实际宽高、体积、你自己的验收句（缩小到 360px 宽是否仍能看出是什么键、什么手势）。

### 代码挂钩（你不用改代码，但路径必须对）

图交到 `jianzi/public/guide/`。前端按上一节的 `GUIDE_BLOCKS` 顺序挂上。`src` 不要改。`alt` 可以按画面微调。

不要写 Markdown，不要改知乎回答卡。

## 4. 风格

**状态：已就绪。**

走 anthropic-art 的 **page-native**（页面原生），不要默认那套满版强调色。技能原文：用象牙 `#FAF9F5` 铺满画布，承载形用 `#F0EEE6` 或 `#E8E6DC` 与底分开。见字卡片纸是 `#f4efe4`，这三色挨着，印上去才是一块色版，不是另一张封面。

锁定：

- 整张画布：象牙 `#FAF9F5`，四角不透明。不要 clay `#D97757`、cactus `#BCD1CA`、heather、sky、fig、coral、olive，也不要用见字的朱红 `--registration` 当底。
- 承载形：不规则，`#F0EEE6` 或 `#E8E6DC`。不要再套一层满版强调色。
- 线条：技能近黑 `#141413`，圆头、粗细不均、略抖。不要纯黑、不要细描线。
- 结构仍是技能的三层（底 + 承载形 + 线），只是底改成象牙，不再是陶土橙/淡绿那种强调色场。
- 键帽字母按 §3：W A S D、方向键、Enter、1 2 3、8 9 0，以及产品里已有的中文标签。除此之外不要句子。这是对技能默认「不要文字」的唯一例外，走 prompt contract 的 `Text (verbatim)`。
- 不要纸纹、渐变、阴影、3D、玻璃、贴纸。卡片本身已有纸纹，图里再画一层会脏。

生成时在调用里写明 `page-native` / 页面原生，并点名上述色值。不要让技能退回满版 accent。

## 5. 审查时盯什么

每张图反复看这几件事，不要一次过就停：

1. 缩小到卡片上的实际宽度（约 360px），还能不能立刻认出键或手势。
2. 有没有变成 UI 截图、教程箭头、游戏 HUD。
3. 有没有玻璃、渐变、3D、贴纸、胶带。
4. WASD 和方向键是否在说同一件事。
5. 触控板和 Windows 鼠标是否都在，没有只画苹果产品。
6. 左标签是收藏，右标签是视图，没有画反。
7. 有没有退回满版陶土橙、淡绿等强调色底。页面原生必须是象牙底。

不合格就改同一张，不要另开一套构图充数。

## 6. 不要做的事

- 不要给知乎回答卡画插图。
- 不要发明第四个收藏标签或第四种视图。
- 不要在图里写「如何使用本产品」这类句子。
- 不要输出 SVG 图标集或透明 sticker。
- 不要改 `DESIGN.md` 的风格定位来迁就默认 skill 配色。风格以 §4 为准。
